# /commit — Workflow: Quality Gate, Docs Sync & Atomic Commit

**Использование:** `/commit [-m "<message>"] [--no-docs] [-h|--help]`

Локальная фиксация промежуточных изменений в текущей рабочей ветке без отправки на remote и создания PR (для полного релиза используется `/ship`).

## Шаги workflow

### 0. Справка (`-h` / `--help`)
Вывести шпаргалку по шагам `/commit` и флагам (`-m` для явного текста коммита, `--no-docs` для пропуска автообновления документации) и остановиться.

### 1. Проверка ветки и безопасности
- Проверить текущую ветку (`git branch --show-current`). Если активна ветка `main` — предупредить пользователя, но не блокировать, если изменения безопасны (или предложить создать ветку).
- Запустить `git status` и `git diff` (включая staged-изменения `git diff --cached`).
- Если изменений нет — сообщить об этом и остановиться.
- Проверить diff на наличие секретов, токенов, ключей API, `.env` или локального мусора. При обнаружении — немедленно остановиться и предупредить.

### 2. Умная проверка качества (Adaptive Quality Gate)
Определить набор проверок на основе списка изменённых файлов (требовать exit code 0):
- **Изменены только `.md` / документация:** Проверить валидность синтаксиса (при наличии Mermaid-блоков убедиться в отсутствии неэкранированных скобок). Линтеры и тесты не запускать.
- **Изменены `.py` файлы в `src/` или `tests/`:** Запустить `ruff check .` и `pytest`.
- **Изменены файлы AI-инфраструктуры (`.kilocode/`, `AGENTS.md`, промпты, vision/LLM-клиенты):** Дополнительно запустить `make ai-smoke`.

Если любая проверка упала — остановиться и исправить ошибки перед коммитом.

### 3. Синхронизация документации (Docs Sync)
Если не указан флаг `--no-docs`, проанализировать `git diff` и при необходимости актуализировать документацию:
- **`docs/user-flows/MVP_PLAN.md`:** Если изменения закрывают или продвигают этап из матрицы готовности — обновить статус в таблице и чек-листах.
- **`docs/user-flows/billing-cycle.md`:** Если в `handlers.py`, `fsm.py` или логике валидации изменились шаги пользователя, кнопки, проверки или переходы статусов — синхронно обновить таблицу и Mermaid-схему.
- Мелкий рефакторинг и багфиксы, не меняющие логику сценария, в документацию не вносить.

### 4. Коммит (без паузы)
- Сформировать лаконичное сообщение в формате Conventional Commits (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`) на английском языке (или использовать текст из флага `-m`, если он передан).
- Добавить все актуальные изменения (включая обновлённую документацию) через `git add` и выполнить `git commit`.
- Вывести краткий отчёт: хэш коммита, сообщение и список закоммиченных файлов.

## Флаги
- `-m "<message>"` — задать собственное сообщение коммита вручную.
- `--no-docs` — пропустить шаг автоматического анализа и обновления `MVP_PLAN.md` и `billing-cycle.md`.
- `-h`, `--help` — показать справку по команде.

## Предварительные требования
- Есть незакоммиченные изменения в working tree или staging area.
- Нет `.env`, ключей и секретов в diff.
- Пройдены релевантные проверки качества.
