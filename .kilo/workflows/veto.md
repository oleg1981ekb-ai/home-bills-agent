# Workflow: /veto

## Роль
Вето-оркестрация: принять/отклонить/вынести на доработку любое решение, задачу или код. Работает только на текстовых эмодзи-статусах 🟢 / 🟡 / 🔴 без вызова внешних инструментов.

## Статусы

- **🟢 — Одобрено**: решение проходит, можно коммитить, мержить, деплоить.
- **🟡 — Доработать**: есть замечания, но не блокирующие. Требуется исправление перед переходом на следующий этап.
- **🔴 — Вето**: категорически не проходит. Мерж/релиз запрещены до устранения критических блокеров.

## Порядок работы

1. **Инициатор** размещает вопрос/код/дизайн в чат с пометкой «Требуется вето».
2. **Уполномоченный** (техлид, security owner, код owner) отвечает одним эмодзи:
   - 🟢 — согласен, всё хорошо.
   - 🟡 — есть мелкие замечания (перечисляет текстом ниже эмодзи).
   - 🔴 — вето (обязательно указывает блокирующие причины текстом).
3. **Если 🔴** — иницииатор исправляет и возвращает на повторное вето.
4. **Если 🟡** — иницииатор устраняет замечания, подтверждает в ответе, затем продолжает `/ship`.
5. **Если 🟢** — сразу переходит к `/ship`.

## Ограничения

- Работает только в текстовом режиме. Не вызывайте инструменты, не запускайте команды, не создавайте файлы.
- Эмодзи — единственный обязательный ответ. Дополнительные комментарии — текстом под эмодзи.
- Вето может наложить только назначенный код owner / техлид / security owner (см. `.github/CODEOWNERS`).
- Для главной ветки `main` вето действует принудительно: мерж без 🟢 запрещён.

## Когда применять

- Перед `/ship` — финальное вето по коду.
- Перед `/branch` — вето на название/формулировку задачи.
- Перед запуском на прод — вето безопасности.
- При любом конфликтном решении — третий голос через вето.

## Связанные workflow

- Используйте с `/ship` для финального подтверждения.
- Используйте с `/crit` для предварительного анализа перед вето.
- Используйте с `/opinion` для сбора позиций перед финальным вето.
