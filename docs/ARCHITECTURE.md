# Архитектура: Home Bills Agent (Anapa Water Agent v1.1)

## 1. Обзор

Telegram-ассистент для передачи показаний и оплаты услуг АО «Анапа Водоканал».
Одно пользовательское приложение в Docker-контейнере на домашнем сервере/мини-ПК.
Python 3.12, aiogram 3, httpx, SQLite (SQLAlchemy), APScheduler, Anthropic API.

## 2. Структура модулей

| Модуль | Путь | Технологии | Назначение |

## 3. Архитектурные принципы

1. **Деньги и состояние — в детерминированном автомате и БД.**
   Модель Claude только читает фото и формулирует сообщения. Решения об отправке показаний и оплате принимает код по правилам (§6 спецификации).

2. **SQLite (`billing_cycles`) — единственный источник истины о состоянии цикла.**
   Не память FSM aiogram. Каждый хендлер перед действием сверяется со статусом активного цикла в одной транзакции.

3. **Режим `DRY_RUN`** (настройка в конфиге):
   Клиент ЛК выполняет всё, кроме реальной отправки `AddCounterValue`. Обязателен на этапе разработки, так как ввод возможен раз в сутки и исправляется только через водоканал.

4. **Провайдер изолирован** в `src/home_bills_agent/providers/anapa_vodokanal/` — готово к расширению под другие ЖКХ-провайдеры.

## 4. Модель данных (SQLite)

### 4.1. `billing_cycles` — основная таблица (составной PK: `account_id`, `period`)

| Поле | Тип | Описание |
|------|-----|----------|
| `account_id`, `period` | TEXT | Составной ключ, период в формате `YYYY-MM` |
| `status` | TEXT | Статус цикла (с индексом) |
| `reading_value` | NUMERIC | Переданное показание |
| `previous_reading` | NUMERIC | Предыдущее показание из ЛК |
| `consumption` | NUMERIC | Расход за период |
| `reading_source` | TEXT | `text` или `photo` |
| `debt_before`, `debt_after` | NUMERIC | Долг до и после передачи, руб. |
| `payment_link` | TEXT | Ссылка на оплату в А3 |
| `paid_marked_at` | TIMESTAMP | Когда пользователь нажал «Оплачено» |
| `payment_verified_at` | TIMESTAMP | Когда снижение долга подтверждено |
| `retry_count`, `next_check_at`, `last_checked_at` | INT / TIMESTAMP | Повторные проверки |
| `created_at`, `updated_at` | TIMESTAMP | Служебные метки |

### 4.2. `readings_cache`

Дата, значение, признак источника (целое/дробное, передано абонентом/рассчитано водоканалом) для расчёта порога аномалии. Обновляется при каждом чтении истории.

### 4.3. `events`

Журнал: время, тип события, краткое описание. Для диагностики и сообщений в `MANUAL_REVIEW`. Лицевой счёт в журнале маскируется.

## 5. Конечный автомат цикла (FSM)

| Статус | Значение |
|--------|----------|
| `WAITING_READING` | Цикл создан, ожидается показание |
| `AWAITING_ANOMALY_CONFIRMATION` | Расход аномальный или значение распознано по фото, ждём подтверждения пользователя |
| `READING_SENT` | Показание отправлено в ЛК, идёт проверка |
| `ACCRUAL_PENDING` | Долг после отправки не изменился, повторные проверки |
| `AWAITING_PAYMENT` | Ссылка на оплату отправлена |
| `PAID` | Пользователь подтвердил оплату (и долг подтверждённо снизился) |
| `CANCELLED` | Отмена пользователем |
| `MANUAL_REVIEW` | Исчерпаны попытки или нештатная ситуация |

### Переходы

| Из | Событие | В |
|----|---------|---|
| — | Наступил период (`WINDOW_START`) | `WAITING_READING` |
| `WAITING_READING` | Показание прошло проверки | `READING_SENT` |
| `WAITING_READING` | Аномалия или значение по фото | `AWAITING_ANOMALY_CONFIRMATION` |
| `AWAITING_ANOMALY_CONFIRMATION` | Пользователь подтвердил | `READING_SENT` |
| `AWAITING_ANOMALY_CONFIRMATION` | Пользователь исправил или отменил | `WAITING_READING` / `CANCELLED` |
| `READING_SENT` | Показание видно в истории, долг прочитан | `AWAITING_PAYMENT` |
| `READING_SENT` | Долг не изменился | `ACCRUAL_PENDING` |
| `ACCRUAL_PENDING` | Повтор через 1, 3, 6 дней: данные появились | `AWAITING_PAYMENT` |
| `ACCRUAL_PENDING` | Попытки исчерпаны | `MANUAL_REVIEW` |
| `AWAITING_PAYMENT` | Кнопка «Оплачено» | `PAID` |

### Идемпотентность

- PRIMARY KEY (`account_id`, `period`) — не более одного цикла на период.
- Не более одного цикла в статусах `READING_SENT`, `ACCRUAL_PENDING`, `AWAITING_PAYMENT` на период.
- Повторное нажатие кнопок обрабатывается повторным чтением статуса в одной транзакции.

## 6. Ввод и проверка показаний

### Источники
- **Текст**: любое сообщение с целым числом. Дробная часть отклоняется с подсказкой (счётчик принимает только целые).
- **Фото**: отправляется в модель Claude с запросом вернуть значение и уверенность в JSON. Фото после обработки удаляется, сохраняется только значение.
- Сообщения без распознаваемого числа — штатный ответ с подсказкой, диалог не ломается.

### Правила проверки

| Проверка | Правило | Действие при нарушении |
|----------|---------|------------------------|
| Не меньше предыдущего | `NewValue` ≥ последнего показания из ЛК | Не отправлять, сообщить пользователю |
| Окно передачи | Сегодня в пределах `WINDOW_START`–`WINDOW_END` | Сообщить, что приём закрыт |
| Один раз в сутки | В этом периоде показание ещё не передавалось | Сообщить уже переданное значение |
| Аномальный расход | Расход в сутки > `ANOMALY_FACTOR` (по умолчанию 2) от медианы по предыдущим интервалам | Показание не отправляется, бот показывает расход и ждёт ручного подтверждения |
| Подтверждение фото | Любое значение, распознанное по фото | Показать распознанное значение и запросить подтверждение одним нажатием |

**Медиана** считается по последним шести интервалам между показаниями. Дробные значения (проставленные водоканалом) исключаются из расчёта — используются только целые, переданные абонентом.

## 7. Планировщик (APScheduler)

| Задача | Расписание | Действие |
|--------|------------|----------|
| Утреннее напоминание | `REMINDER_START_DAY` (18)–`WINDOW_END`, ежедневно в `REMINDER_TIME` (09:00) | Создать цикл при необходимости, напомнить, пока показание не передано |
| Вечернее напоминание | С `EVENING_FROM_DAY` (22) по `WINDOW_END`, в `EVENING_TIME` (19:00) | Повторить напоминание, если показание не передано |
| Повторные проверки | Для `ACCRUAL_PENDING`: через 1, 3, 6 дней | Перечитать долг; при исчерпании перейти в `MANUAL_REVIEW` |
| Проверка оплаты | Через 1 и 3 дня после «Оплачено» | Перечитать долг и сообщить результат |
| Сверка активного цикла | Ежедневно, при старте | Найти цикл со статусом ≠ `PAID` и ≠ `CANCELLED`, и продолжить |
| Резервная копия | Ежедневно | Копия SQLite, хранить 14 дней |

Все расписания и часовой пояс задаются в конфигурации (по умолчанию `Europe/Moscow`).

## 8. Оплата

- Бот формирует ссылку `https://andromeda.a-3.ru/6172/?PERSONAL_ACCOUNT=ACCOUNT_ID` и присылает её вместе с суммой долга, прочитанной из ЛК.
- Сервис А3 сам подставляет «Итого к оплате», комиссия при оплате картой 0 руб. (на 24.11.2026).
- Пользователь вводит телефон и данные карты на странице А3. Бот эти данные не видит и не хранит.
- Бот не нажимает кнопки оплаты и не автоматизирует платёжные страницы.
- Кнопка «Оплачено» переводит цикл в `PAID`; последующая проверка долга сообщает, подтвердился ли платёж.
- Сумма долга может включать прошлые задолженности. Бот показывает долг целиком, а если из HTML удаётся выделить начисление за текущий период — то и его отдельно.

## 9. Нефункциональные требования

### 9.1. Безопасность
- Доступ только для пользователя из `TELEGRAM_USER_ID`.
- Секреты (токен бота, логин/пароль ЛК, ключ Anthropic API) только в `.env` или Docker secrets, не в коде, не в БД, не в логах.
- В логах маскируются лицевой счёт, токены защиты, cookie и ссылки с параметрами.
- Пароль ЛК после настройки заменяется на новый; значения из тестовых скриншотов и переписки считаются скомпрометированными.
- Фото счётчика не хранится после распознавания.

### 9.2. Надёжность
- Сессия ЛК переиспользуется; при редиректе на страницу входа клиент входит заново. Число попыток входа ограничено, чтобы не вызвать капчу.
- При появлении капчи или смене разметки (не найден ожидаемый признак на странице) бот сообщает пользователю и переводит цикл в `MANUAL_REVIEW`, приложив фрагмент HTML.
- Сетевые сбои: экспоненциальные задержки и повторы; бот сообщает, если ЛК недоступен дольше заданного времени.
- Контейнер запускается с политикой перезапуска `unless-stopped`; при старте планировщик восстанавливает активный цикл из БД.
- Бот раз в сутки отправляет сигнал живости только при наличии проблем (молчание нормы не засоряет чат).

### 9.3. Хостинг на мини-ПК
- Автозапуск после перезагрузки, синхронизация времени, проверка доступности `abonent.vodokanal.net` и `api.anthropic.com` при старте.
- Резервные копии SQLite хранятся вне контейнера.

## 11. Риски и открытые вопросы (из спецификации §12)

| Вопрос | Статус |
|--------|--------|
| Доступен ли ЛК с IP мини-ПК | Закрыто: ЛК открывается |
| Целые значения — абонент, дробные — водоканал | Подтверждено владельцем |
| Принимает ли ЛК дробные показания | Закрыто: только целые |
| Часовой пояс напоминаний | Закрыто: `Europe/Moscow` |
| Ежедневные напоминания с 1-го числа | Закрыто: с 18-го (`REMINDER_START_DAY`) |
| Ошибка распознавания фото | Закрыто: всегда подтверждение одним нажатием |
| Пути `CounterInfo` и `HistoryCounter` | Снять при реализации |
| Условия использования ЛК | Низкая частота, один пользователь, без обхода защиты |
