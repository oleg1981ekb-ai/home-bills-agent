# Architecture Decision Records (ADR)

Ранее принятые архитектурные решения проекта Home Bills Agent (Anapa Water Agent).
Формат: Status / Context / Decision / Consequences.

## ADR-001: Прямые HTTP-запросы (httpx + HTML-разметка) вместо Playwright

- **Status:** Accepted
- **Context:** Для автоматизации личного кабинета АО «Анапа Водоканал» (abonent.vodokanal.net, ASP.NET MVC) из домашнего сервера требовалась автоматическая авторизация и чтение/передача показаний. Playwright был бы избыточен.
- **Decision:** Использовать прямые HTTP-запросы (httpx) с поддержкой сессии через HttpOnly cookie и разбором HTML по устойчивым признакам (подписи, структура таблицы), а не по позициям. Playwright — только запасной вариант.
- **Consequences:** Сокращение сложности и ресурсов контейнера; при смене разметки нужно обновлять парсеры; требуется аккуратная работа с `__RequestVerificationToken`.

## ADR-002: SQLite (`billing_cycles`) как источник истины вместо aiogram FSM

- **Status:** Accepted
- **Context:** Необходимо восстановление состояния после перезапуска, идемпотентность (один цикл на период) и детерминированный источник правды.
- **Decision:** Детерминированный FSM хранить в SQLite (таблица `billing_cycles`, составной PK `account_id` + `period`). Память FSM aiogram не используется как источник состояния; каждый хендлер сверяется со статусом активного цикла в БД.
- **Consequences:** Транзакционная проверка идемпотентности, работоспособность после перезапуска контейнера; усложнение доступа к FSM; необходимость миграций БД.

## ADR-003: Делегирование оплаты сервису А3 вместо локальной генерации QR ST00012

- **Status:** Accepted
- **Context:** Сумма задолженности формируется в ЛК; для оплаты требовалась платёжная страница.
- **Decision:** Формировать и передавать пользователям ссылку на платёжный сервис А3 (`https://andromeda.a-3.ru/6172/?PERSONAL_ACCOUNT=...`), сумма подставляется сервисом. Автоматическая оплата и перехват SMS не входит в область применения; бот не нажимает кнопки оплаты.
- **Consequences:** Пользователь вводит телефон/карту/3-D Secure на странице А3; бот не хранит платёжные данные; проверка оплаты выполняется через повторную проверку долга (кнопка «Оплачено» → `PAID`).

## ADR-004: Использование одобренной модели claude-sonnet-4-5 (Anthropic) исключительно для OCR счётчика

- **Status:** Accepted
- **Context:** Требовалось распознавание значения счётчика по фото, уверенность модели должна быть валидирована.
- **Decision:** Использовать только одобренную в `.kilo/approved_models.yaml` модель `claude-sonnet-4-5` (Anthropic) для распознавания фото счётчика; обязательное подтверждение пользователем (одним нажатием); фото после распознавания удаляется, сохраняется только значение.
- **Consequences:** Соответствие политике AI-инфраструктуры; обязательное подтверждение снижает риск ошибок; удаление медиа после обработки снижает риск хранения чувствительных данных.

## ADR-005: Расчёт медианы суточного потребления только из целых показаний абонента

- **Status:** Accepted
- **Context:** В истории ЛК встречаются как целые, так и дробные значения (например, 569,63). Дробные значения, вероятно, начислены водоканалом расчётным способом; предположение подтверждено владельцем. Счётчик принимает только целые значения.
- **Decision:** Медиана суточного расхода считается только по интервалам между целыми показаниями, переданными абонентом (дробные исключены из расчёта). Порог аномалии (`ANOMALY_FACTOR`, по умолчанию 2) применяется к расходу в расчёте на сутки.
- **Consequences:** Более точные и предсказуемые проверки аномалий; дробные значения не влияют на пороги расчёта.
