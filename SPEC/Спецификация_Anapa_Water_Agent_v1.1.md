# **Спецификация Anapa Water Agent v1.1**

Telegram-ассистент передачи показаний и оплаты услуг АО «Анапа Водоканал». Версия 1.1 от 24.11.2026. Заменяет v1.0 по итогам разведки личного кабинета и решений владельца.

## **1. Что изменилось относительно v1.0**

| Тема | v1.0 | v1.1 |
| - | - | - |
| Доступ к ЛК | Playwright | Прямые HTTP-запросы (httpx) с разбором HTML; Playwright только запасной вариант |
| Тип показаний | INTEGER | NUMERIC (в ЛК бывают дробные значения, например 569,63) |
| Окно передачи | 18–24 число | 1–25 число (так указано в форме ЛК), границы в конфиге |
| Оплата | QR ST00012 | Ссылка на платёжный сервис А3, сумма подставляется сервисом |
| Ввод показаний | Число в чат | Фото счётчика, текст; бот сам напоминает |
| Самостоятельность | Подтверждение на каждом шаге | Всё делает сам, подтверждения требуют только оплата и аномальный расход |
| Порог расхода | Фиксированно 5–8 м³ | Считается по истории конкретного счётчика |
| Голос | Нет | Не делаем в этой версии (возможное расширение) |
| Хостинг | Контейнер | Домашний сервер или мини-ПК, Docker |

## **2. Цели и границы**

### **2.1. Цели**

- Убрать ручной ежемесячный ритуал: вспомнить, зайти в ЛК, ввести показание, дождаться начисления, найти оплату.

- Принимать показание любым удобным способом (фото или текст) и напоминать, когда пора.

- Исключить ошибки ввода до отправки в ЛК.

- Исключить повторную отправку и повторную оплату за один период.

- Восстанавливаться после перезапуска без потери состояния.

### **2.2. Границы**

- Один пользователь, один лицевой счёт, один прибор учёта (холодная вода).

- Оплату выполняет пользователь на странице сервиса А3 (телефон, карта, 3-D Secure). Автоматическая оплата и перехват SMS не входят в область применения.

- Сумма всегда берётся из ЛК или сервиса А3, самостоятельный расчёт по тарифам запрещён.

- Голосовой ввод в эту версию не входит.

## **3. Результаты разведки ЛК**

Сайт: abonent.vodokanal.net, платформа на ASP.NET MVC (IIS 7.5). Вход по логину и паролю, капчи и кода по SMS при входе не было. На страницах подключён модуль BotDetectCaptcha, поэтому капча может включаться при подозрительной активности.

| Действие | Запрос | Поля и особенности | Ответ |
| - | - | - | - |
| Вход | POST /fl/Account/Login | \_\_RequestVerificationToken, Login, Password, RememberMe | 302 на /fl/UserPage; сессия в HttpOnly cookie webauthcookies |
| Главная страница | GET /fl/UserPage?account=ACCOUNT\_ID | Содержит токен защиты в скрытом поле, блок «Долг», финансовую карточку, тарифы | HTML |
| История показаний | POST /fl/UserPage/ShowHistoryCounter?Length=8 | CounterCode, IdDb=1, \_\_RequestVerificationToken, заголовок X-Requested-With: XMLHttpRequest | HTML-таблица «дата, показание» |
| Информация о счётчике | GET CounterInfo?counterCode=… | Дата и значение последних показаний, статус счётчика | HTML (точный путь и параметры уточнить) |
| Передача показаний | POST /fl/UserPage/AddCounterValue | \_\_RequestVerificationToken, idDb=1, Code, LastValue, NewValue | 302 на /fl/UserPage?account=ACCOUNT\_ID; на странице сообщение «Новые показания успешно переданы» |
| Квитанция | POST /fl/UserPage/PrintReceipt | idDb, subscriberCode, selectedMonth | Картинка JPEG; ботом не используется, данные берутся из HTML |
| Оплата | GET https://andromeda.a-3.ru/6172/?PERSONAL\_ACCOUNT=ACCOUNT\_ID | Лицевой счёт подставляется из ссылки; в форме «Итого к оплате» равно текущему долгу | Страница платёжного сервиса А3 |

Наблюдения, влияющие на дизайн:

- Показания принимаются с 1 по 25 число текущего месяца, ввод возможен один раз в сутки. Исправление ошибочного показания только через сотрудников водоканала (электронная почта или телефон), поэтому ошибка ввода дорогая.

- В истории встречаются как целые, так и дробные значения. Дробные, вероятно, начислены водоканалом расчётным способом, целые переданы абонентом. Предположение подтверждено владельцем.

- После передачи показаний сумма долга на странице обновляется сразу, а не через дни.

- Токен \_\_RequestVerificationToken выдаётся вместе со страницей и парой к cookie, его нужно брать заново с актуальной страницы.

- Ответы приходят в HTML, а не в JSON. Разбор делается по устойчивым признакам (подписи, структура таблицы), а не по позициям.

## **4. Архитектура**

Python 3.12, одно приложение в Docker-контейнере на мини-ПК.

| Модуль | Технологии | Назначение |
| - | - | - |
| bot/ | aiogram 3 | Telegram-интерфейс, приём текста и фото, кнопки, доступ по белому списку TELEGRAM\_USER\_ID |
| assistant/ | Anthropic API (модель с поддержкой изображений) | Распознавание числа на фото счётчика, оценка уверенности |
| vodokanal\_client/ | httpx, selectolax или BeautifulSoup | Вход, поддержка сессии, чтение истории, долга и счётчика, передача показаний |
| payment/ | — | Формирование ссылки на А3 и напоминания об оплате |
| storage/ | SQLite, SQLAlchemy | Единственный источник истины: циклы, показания, события |
| scheduler/ | APScheduler | Напоминания, повторные проверки, проверка оплаты, резервные копии |

Принципы:

- Деньги и состояние живут в детерминированном автомате и БД. Модель Claude только читает фото и формулирует сообщения, решения об отправке и оплате принимает код по правилам из раздела 6.

- Источником истины о состоянии цикла служит таблица billing\_cycles, а не память FSM aiogram. Каждый хендлер перед действием сверяется со статусом активного цикла.

- Режим DRY\_RUN: клиент ЛК выполняет всё, кроме реальной отправки AddCounterValue. Обязателен на этапе разработки, так как ввод возможен раз в сутки и исправляется только через водоканал.

## **5. Пользовательский сценарий**

1. С 18-го по 25-е число каждый день в 09:00 бот напоминает передать показания и называет последнее значение и дату. Начиная с 22-го числа добавляется вечернее напоминание в 19:00. После передачи показаний за месяц напоминания прекращаются.

2. Пользователь присылает показание текстом или фото счётчика.

3. Бот извлекает число и проверяет его (раздел 6).

4. Если проверки пройдены (для фото после подтверждения одним нажатием), бот сам отправляет показание в ЛК и сообщает: «Передано: N. Расход: X м³».

5. Бот перечитывает историю и долг из ЛК, убеждается, что новое показание появилось, и присылает сообщение с суммой долга и кнопкой со ссылкой на оплату А3.

6. Пользователь оплачивает на странице А3 и нажимает «Оплачено».

7. Через 1–3 дня бот перечитывает долг и сообщает, подтвердилась ли оплата.

После каждого успешного шага бот присылает короткое сообщение (показания переданы, начисление получено, долг изменился).

## **6. Ввод и проверка показаний**

### **6.1. Источники ввода**

- Текст: любое сообщение с целым числом (счётчик принимает только целые значения); дробная часть отклоняется с подсказкой.

- Фото: изображение отправляется в модель Claude с запросом вернуть значение счётчика и уверенность в формате JSON. Само фото после обработки удаляется, сохраняется только значение.

- Сообщения без распознаваемого числа получают штатный ответ с подсказкой, диалог не ломается.

### **6.2. Правила проверки**

| Проверка | Правило | Действие при нарушении |
| - | - | - |
| Не меньше предыдущего | NewValue не меньше последнего показания из ЛК | Не отправлять, сообщить пользователю |
| Окно передачи | Сегодня в пределах WINDOW\_START–WINDOW\_END | Сообщить, что приём закрыт |
| Один раз в сутки | В этом периоде показание ещё не передавалось | Сообщить уже переданное значение |
| Аномальный расход | Расход в расчёте на сутки больше ANOMALY\_FACTOR (по умолчанию 2) от медианы по предыдущим интервалам | Показание не отправляется, бот показывает расход и ждёт ручного подтверждения |
| Подтверждение фото | Любое значение, распознанное по фото | Показать распознанное значение и запросить подтверждение одним нажатием |

Медиана считается по последним шести интервалам между показаниями. Дробные значения проставлены водоканалом (подтверждено владельцем), поэтому они исключаются из расчёта.

## **7. Конечный автомат цикла**

| Статус | Значение |
| - | - |
| WAITING\_READING | Цикл создан, ожидается показание |
| AWAITING\_ANOMALY\_CONFIRMATION | Расход аномальный или значение распознано по фото, ждём подтверждения пользователя |
| READING\_SENT | Показание отправлено в ЛК, идёт проверка |
| ACCRUAL\_PENDING | Долг после отправки не изменился, повторные проверки |
| AWAITING\_PAYMENT | Ссылка на оплату отправлена |
| PAID | Пользователь подтвердил оплату (и долг подтверждённо снизился) |
| CANCELLED | Отмена пользователем |
| MANUAL\_REVIEW | Исчерпаны попытки или нештатная ситуация |

Переходы:

| Из | Событие | В |
| - | - | - |
| — | Наступил период (WINDOW\_START) | WAITING\_READING |
| WAITING\_READING | Показание прошло проверки | READING\_SENT |
| WAITING\_READING | Аномалия или значение распознано по фото | AWAITING\_ANOMALY\_CONFIRMATION |
| AWAITING\_ANOMALY\_CONFIRMATION | Пользователь подтвердил | READING\_SENT |
| AWAITING\_ANOMALY\_CONFIRMATION | Пользователь исправил или отменил | WAITING\_READING / CANCELLED |
| READING\_SENT | Показание видно в истории, долг прочитан | AWAITING\_PAYMENT |
| READING\_SENT | Долг не изменился | ACCRUAL\_PENDING |
| ACCRUAL\_PENDING | Повтор через 1, 3, 6 дней: данные появились | AWAITING\_PAYMENT |
| ACCRUAL\_PENDING | Попытки исчерпаны | MANUAL\_REVIEW |
| AWAITING\_PAYMENT | Кнопка «Оплачено» | PAID |

Идемпотентность: PRIMARY KEY (account\_id, period); не более одного цикла в статусах READING\_SENT, ACCRUAL\_PENDING, AWAITING\_PAYMENT на период; повторное нажатие кнопок обрабатывается повторным чтением статуса в одной транзакции.

## **8. Модель данных**

### **8.1. billing\_cycles**

| Поле | Тип | Описание |
| - | - | - |
| account\_id, period | TEXT | Составной ключ, период в формате YYYY-MM |
| status | TEXT | Статус цикла, с индексом |
| reading\_value | NUMERIC | Переданное показание |
| previous\_reading | NUMERIC | Предыдущее показание из ЛК |
| consumption | NUMERIC | Расход за период |
| reading\_source | TEXT | text или photo |
| debt\_before, debt\_after | NUMERIC | Долг до и после передачи, руб. |
| payment\_link | TEXT | Ссылка на оплату в А3 |
| paid\_marked\_at | TIMESTAMP | Когда пользователь нажал «Оплачено» |
| payment\_verified\_at | TIMESTAMP | Когда снижение долга подтверждено |
| retry\_count, next\_check\_at, last\_checked\_at | INT / TIMESTAMP | Повторные проверки |
| created\_at, updated\_at | TIMESTAMP | Служебные метки |

### **8.2. readings\_cache**

Дата, значение, признак источника (целое или дробное, передано абонентом или рассчитано) для расчёта порога. Обновляется при каждом чтении истории.

### **8.3. events**

Журнал: время, тип события, краткое описание. Нужен для диагностики и сообщений в MANUAL\_REVIEW. Лицевой счёт в журнале маскируется.

## **9. Планировщик**

| Задача | Расписание | Действие |
| - | - | - |
| Утреннее напоминание | REMINDER\_START\_DAY (18)–WINDOW\_END, ежедневно в REMINDER\_TIME (09:00) | Создать цикл при необходимости, напомнить, пока показание не передано |
| Вечернее напоминание | С EVENING\_FROM\_DAY (22) по WINDOW\_END, в EVENING\_TIME (19:00) | Повторить напоминание, если показание не передано |
| Повторные проверки | Для ACCRUAL\_PENDING: через 1, 3, 6 дней | Перечитать долг; при исчерпании перейти в MANUAL\_REVIEW |
| Проверка оплаты | Через 1 и 3 дня после «Оплачено» | Перечитать долг и сообщить результат |
| Сверка активного цикла | Ежедневно, при старте | Найти цикл со статусом, не равным PAID и CANCELLED, и продолжить |
| Резервная копия | Ежедневно | Копия SQLite, хранить 14 дней |

Все расписания и часовой пояс задаются в конфигурации, а не в коде.

## **10. Оплата**

- Бот формирует ссылку https://andromeda.a-3.ru/6172/?PERSONAL\_ACCOUNT=ACCOUNT\_ID и присылает её вместе с суммой долга, прочитанной из ЛК.

- Сервис А3 сам подставляет «Итого к оплаты», комиссия при оплате картой 0 руб. (по состоянию на 24.11.2026). Сумма в сообщении бота нужна для ориентира и сверки.

- Пользователь вводит телефон и данные карты на странице А3. Бот эти данные не видит и не хранит.

- Бот не нажимает кнопки оплаты и не автоматизирует платёжные страницы.

- Кнопка «Оплачено» переводит цикл в PAID; последующая проверка долга сообщает, подтвердился ли платёж.

- Сумма долга может включать прошлые задолженности. Бот показывает долг целиком, а если из HTML удаётся выделить начисление за текущий период, то и его отдельно.

## **11. Нефункциональные требования**

### **11.1. Безопасность**

- Доступ только для пользователя из TELEGRAM\_USER\_ID.

- Секреты (токен бота, логин и пароль ЛК, ключ Anthropic API) только в .env или Docker secrets, не в коде, не в БД, не в логах.

- В логах маскируются лицевой счёт, токены защиты, cookie и ссылки с параметрами.

- Пароль ЛК после настройки заменяется на новый, значения из тестовых скриншотов и переписки считаются скомпрометированными.

- Фото счётчика не хранится после распознавания.

### **11.2. Надёжность**

- Сессия ЛК переиспользуется; при редиректе на страницу входа клиент входит заново. Число попыток входа ограничено, чтобы не вызвать капчу.

- При появлении капчи или смене разметки (не найден ожидаемый признак на странице) бот сообщает пользователю и переводит цикл в MANUAL\_REVIEW, приложив фрагмент HTML.

- Сетевые сбои: экспоненциальные задержки и повторы; бот сообщает, если ЛК недоступен дольше заданного времени.

- Контейнер запускается с политикой перезапуска unless-stopped; при старте планировщик восстанавливает активный цикл из БД.

- Бот раз в сутки отправляет сигнал живости только при наличии проблем (молчание нормы не засоряет чат).

### **11.3. Хостинг на мини-ПК**

- Автозапуск после перезагрузки, синхронизация времени, проверка доступности abonent.vodokanal.net и api.anthropic.com при старте.

- Резервные копии SQLite хранятся вне контейнера.

## **15. План реализации**

1. vodokanal\_client: вход, чтение истории, долга и счётчика, разбор HTML. Проверка из командной строки на мини-ПК, только чтение.

2. storage и автомат состояний с тестами переходов и идемпотентности.

3. Бот: приём текста, проверка, режим DRY\_RUN, сообщения после каждого шага.

4. Планировщик: напоминания в 09:00 и 19:00, повторные проверки, восстановление после перезапуска.
